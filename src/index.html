  • How to control allowed visitors

    Site owner can appoint a site admin or issue a grant record for the specified visitor to grant edit access to a table.
    Later the Site Owner can mark a grant record as deleted.
    Validity of access will be checked periodically during the maintenance. (Enforced by the Serveronet client)

  • Functional enpoints
    Every Serveronet Site has following endpoints. See this site's script for usage examples or API Documentation

    • query_endpoint - Endpoint for user data queries. You can use a subset of sql DQLs to retrieve the needed records.
    • visitor_record_create - Backend to create new record. Requires authenticated visitor.
    • visitor_record_update - Backend update a record. Requires authenticated visitor.
    • visitor_files - Listing of visitor files. Requires authenticated visitor.
    • visitor_file_upload - Upload Visitor's file.
    • visitor_file_delete - Enpoint to mark Visitor File as deleted.
    • check_can_post_to_table - Check if Visitor can post to a specified table.
    • check_can_upload - Check if Visitor can upload files.
    • login - Route to redirect visitor if authentication is required
    • logout - Logout from Site
    • is_authenticated - Enpoint to quickly check if current visitor is authenticated
    • get_visitor_state - Site can verify if current user can post and upload files
    • csrf-cookie - Enpoint to regerate CSRF cookie. Just request it.
    • site_state - Enpoint to quickly check Site details
    • client_config - Enpoint to check configuration of the Serveronet client
